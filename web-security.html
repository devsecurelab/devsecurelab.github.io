🟢 Beginner Track

Module 1: Web Architecture & HTTP Security Headers

Estimated: 35 mins

Objective: Inspect client-server request cycles, understand HTTP response headers, and configure browser security controls.

Concept: Security headers like Content-Security-Policy (CSP), Strict-Transport-Security (HSTS), and X-Frame-Options instruct browsers to enforce strict safety boundaries.

# Recommended Response Headers:
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Content-Security-Policy: default-src 'self'

Practice Task: Inspect response headers on your local dev server using browser Developer Tools (F12 -> Network tab).

Knowledge Check: Which HTTP response header prevents a web application from being rendered inside an `<iframe>` to stop Clickjacking?

Module 2: OWASP Top 10 Vulnerability Framework

Estimated: 40 mins

Objective: Understand the OWASP Top 10 methodology for identifying and prioritizing critical web security risks.

Concept: OWASP provides a standard security blueprint categorized by flaw frequency, impact, and remediation complexity.

OWASP Key Categories:
- A01: Broken Access Control
- A02: Cryptographic Failures
- A03: Injection

Practice Task: Read the summary description of "Broken Access Control" on the official OWASP project page.

Knowledge Check: What organization publishes the widely accepted OWASP Top 10 security standard?

Module 3: Same-Origin Policy (SOP) & CORS

Estimated: 35 mins

Objective: Analyze browser isolation mechanisms, origin parameters (Protocol, Host, Port), and Cross-Origin Resource Sharing (CORS).

Concept: SOP prevents scripts on one domain from accessing sensitive data on another origin unless explicitly allowed via CORS headers.

Origin Components: [Protocol] :// [Hostname] : [Port]
Example: https://example.com:443

Practice Task: Determine if `http://example.com` and `https://example.com` are considered the same origin (No, protocol differs).

Knowledge Check: What three elements define a web origin under the Same-Origin Policy?

🔵 Intermediate Track

Module 4: Cross-Site Scripting (XSS) & Contextual Encoding

Estimated: 45 mins

Objective: Distinguish between Stored, Reflected, and DOM-based XSS, and apply contextual HTML output encoding.

Concept: XSS occurs when untrusted user input is rendered in the browser without proper sanitization or output encoding.

<div>Welcome, <?php echo $_GET['user']; ?></div>

<div>Welcome, <?php echo htmlspecialchars($_GET['user'], ENT_QUOTES, 'UTF-8'); ?></div>

Practice Task: Identify which character encoding converts `<` into `&lt;` to neutralize HTML tags safely.

Knowledge Check: What primary defense mechanism mitigates Cross-Site Scripting (XSS) when rendering user data in HTML?

Module 5: SQL Injection (SQLi) & Prepared Statements

Estimated: 45 mins

Objective: Analyze SQL injection mechanics and remediate flaws using Parameterized Queries (Prepared Statements).

Concept: Concatenating untrusted user input directly into database queries lets attackers alter query logic entirely.

# Secure Python Parameterized Query:
cursor.execute("SELECT * FROM users WHERE username = %s AND status = %s", (user_input, "active"))

Practice Task: Review a database query in your favorite language and ensure input variables are passed as parameters.

Knowledge Check: What is the primary defense against SQL Injection vulnerabilities?

Module 6: CSRF Defenses & SameSite Cookies

Estimated: 40 mins

Objective: Prevent Cross-Site Request Forgery (CSRF) using Anti-CSRF tokens and proper `SameSite` cookie flags.

Concept: CSRF tricks a victim's web browser into making unauthorized HTTP requests to a target site where they are authenticated.

Set-Cookie: session_id=xyz123; Secure; HttpOnly; SameSite=Strict

Practice Task: Verify that sensitive HTML state-changing forms in your projects contain unique, cryptographically secure anti-CSRF tokens.

Knowledge Check: Which `SameSite` cookie attribute value prevents cookies from being sent on cross-site requests entirely?

🟣 Advanced Track

Module 7: Authentication & Session Security

Estimated: 45 mins

Objective: Implement secure password hashing (Argon2, bcrypt), MFA workflows, session token generation, and secure storage.

Concept: Passwords must never be stored in cleartext or MD5/SHA1. Session tokens must use high entropy and explicit expiration.

# Recommended Password Hashing Algorithms:
1. Argon2id (Winner of Password Hashing Competition)
2. bcrypt (Work factor >= 12)
3. PBKDF2 with HMAC-SHA256

Practice Task: Verify that local web projects use strong password hashing libraries rather than plain MD5 or SHA256 hashes.

Knowledge Check: Why is plain MD5 or SHA256 considered unsafe for storing user passwords?

Module 8: Web Security Audit & Code Review Project

Estimated: 50 mins

Objective: Conduct a comprehensive static code review and security assessment on a sample web application repository.

Concept: Systematic code reviews combine automated static analysis (SAST) with manual inspection of access control and logic.

# Audit Checklist Blueprint:
1. Check authentication routes & session flags
2. Audit database queries for parameterized syntax
3. Verify contextual HTML output encoding on user inputs
4. Validate authorization checks on every sensitive endpoint

Practice Task: Perform a self-audit on a local web project using the 4-step checklist above and document findings.

Knowledge Check: What type of security assessment analyzes source code directly without executing the application?

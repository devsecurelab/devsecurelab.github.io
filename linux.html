🟢 Beginner Track

Module 1: Filesystem Structure & Navigation

Estimated: 25 mins

Objective: Understand the Linux Root Hierarchy (`/`, `/etc`, `/var`, `/home`) and navigate using absolute vs relative paths.

Concept: Everything in Linux is a file. The root directory `/` is the base of the entire file system hierarchy.

# Print working directory
pwd

# List all files including hidden ones with detailed attributes
ls -la /var/log

Practice Task: Navigate to `/etc` directory and list files sorted by modification time using `ls -lt`.

Knowledge Check: Which command shows your current working directory path?

Module 2: File Creation & Text Viewing

Estimated: 30 mins

Objective: Safely create, copy, view, and inspect text files without corrupting system files.

Concept: Use `cat` for small files, `less` for pagination, and `head`/`tail` for inspecting log limits.

touch incident_notes.txt
head -n 20 /var/log/syslog
tail -f /var/log/syslog

Practice Task: Create a dummy file named `audit.txt` and append text using `echo "Audit Started" >> audit.txt`.

Knowledge Check: Which command actively follows continuous updates appended to a file?

Module 3: Permissions & Ownership

Estimated: 35 mins

Objective: Configure POSIX read (4), write (2), and execute (1) permissions using numeric octal notation.

Concept: Linux enforces access control via User, Group, and Others triplets (`rwx-r--r--`).

# Secure private SSH key file so only owner can read/write
chmod 600 id_rsa
# Make script executable
chmod +x audit.sh

Practice Task: Set permission on a file so the owner has full rights, group has read-only, and others have no rights (`740`).

Knowledge Check: What octal mode sets Read/Write for Owner and Read-Only for Group and Others?

🔵 Intermediate Track

Module 4: User & Process Management

Estimated: 35 mins

Objective: Monitor active processes, inspect process IDs (PID), and handle background services safely.

Concept: Every program running on Linux is assigned a unique PID managed by the kernel or `systemd`.

ps aux | grep nginx
top
systemctl status sshd

Practice Task: Use `ps aux` piped into `grep` to find the process ID of your current running shell.

Knowledge Check: Which command is used to check the operational status of system services?

Module 5: Log Analysis with Grep & Pipes

Estimated: 40 mins

Objective: Extract operational insights and security incidents from system logs using text filter chains.

Concept: Combining `grep`, `awk`, `sort`, and `uniq` allows searching millions of log lines instantly.

grep "Failed password" /var/log/auth.log | awk '{print $11}' | sort | uniq -c

Practice Task: Extract lines containing "ERROR" from a sample log file and count their unique occurrences.

Knowledge Check: What operator connects the stdout of one command directly into the stdin of another?

Module 6: Linux Networking Commands

Estimated: 35 mins

Objective: Inspect network interfaces, listening ports, local sockets, and remote host connectivity.

Concept: Use native tools to diagnose networking layers locally before troubleshooting remote apps.

ip a
ss -tuln
ping -c 4 127.0.0.1

Practice Task: Run `ss -tuln` to view all active TCP and UDP listening sockets on your system.

Knowledge Check: Which command replaces legacy `netstat` to view listening sockets and ports?

🟣 Advanced Track

Module 7: Bash Shell Automation

Estimated: 45 mins

Objective: Write executable Bash scripts utilizing variables, conditional checks, and exit codes.

Concept: Automation scripts reduce administrative errors and automate security log checks.

#!/bin/bash
LOG_FILE="/var/log/auth.log"
if [ -f "$LOG_FILE" ]; then
  echo "Log exists. Checking failed logins..."
  grep "Failed password" "$LOG_FILE" | wc -l
fi

Practice Task: Create a script `check_disk.sh` that alerts if root disk usage exceeds threshold limits.

Knowledge Check: What line must be included at the very top of a Bash script to define the interpreter?

Module 8: System Audit & Hardening Project

Estimated: 50 mins

Objective: Apply system hardening controls, disable unnecessary services, and audit SUID binaries.

Concept: Reducing attack surface by removing unneeded permissions and restricting root access.

# Search for world-writable files
find / -perm -2 -type f 2>/dev/null
# Audit SUID root files
find / -perm -4000 -type f 2>/dev/null

Practice Task: Execute SUID binary discovery in a disposable environment and document findings.

Knowledge Check: What risk is associated with misconfigured SUID binaries on Linux systems?

🟢 Beginner Track

Module 1: Legal Frameworks & Scope Boundaries

Estimated: 30 mins

Objective: Understand Rules of Engagement (RoE), legal authorization, and written scope boundaries before conducting security assessments.

Concept: Ethical security testing differs from unauthorized activity through explicit prior written consent and strict scope compliance.

# Essential RoE Elements:
1. Explicitly written authorization document
2. Defined IP address ranges and forbidden targets
3. Allowed testing window / timeframe

Practice Task: Identify key components required in an authorized Penetration Testing Rules of Engagement (RoE) contract.

Module 2: Open Source Intelligence (OSINT) & Passive Recon

Estimated: 35 mins

Objective: Gather passive intelligence using public registries, DNS records, WHOIS data, and search engine operators.

Concept: Passive reconnaissance discovers target assets without directly sending packets to target systems.

# Passive DNS lookup for local testing domains
whois example.com
dig example.com ANY

Practice Task: Query WHOIS database information for `example.com` and review domain registrar details.

Knowledge Check: What defines "Passive Reconnaissance" compared to active network scanning?

Module 3: Network Port Scanning & Service Discovery

Estimated: 40 mins

Objective: Perform network port scanning, service banner grabbing, and OS detection against authorized local lab environments.

Concept: Active scanning maps listening network services to evaluate exposure surface area on authorized target machines.

# Scan local loopback test server safely
nmap -sV -sC -p 22,80,443 127.0.0.1

Practice Task: Run `nmap` against local host `127.0.0.1` to list open local development ports.

🔵 Intermediate Track

Module 4: Vulnerability Assessment & CVSS Scoring

Estimated: 40 mins

Objective: Categorize known security vulnerabilities using CVE database identifiers and calculate severity with CVSS v3/v4 metrics.

Concept: Common Vulnerabilities and Exposures (CVE) provides standardized naming for public security bugs.

CVSS Metric Ratings:
- Low: 0.1 - 3.9
- Medium: 4.0 - 6.9
- High: 7.0 - 8.9
- Critical: 9.0 - 10.0

Practice Task: Look up a known CVE (e.g., Log4Shell CVE-2021-44228) in the National Vulnerability Database (NVD).

Knowledge Check: What score range on the CVSS scale represents a "Critical" severity security flaw?

Module 5: Exploitation Fundamentals & POC Validation

Estimated: 45 mins

Objective: Understand Proof-of-Concept (PoC) code execution dynamics safely in isolated laboratory environments.

Concept: Validating vulnerabilities via PoC testing confirms whether potential flaws pose actionable risk to target infrastructure.

# Safe PoC Verification Cycle:
1. Review PoC code line-by-line before running
2. Test inside isolated VM host without external routing
3. Verify impact on target process behavior

Practice Task: Set up a local isolated virtual machine to safely inspect test scripts.

Knowledge Check: Why must security analysts inspect third-party Proof-of-Concept (PoC) scripts before running them?

Module 6: Privilege Escalation Concepts & Auditing

Estimated: 45 mins

Objective: Identify misconfigured SUID binaries, unsafe sudo permissions, and unpatched kernel vulnerabilities locally.

Concept: Privilege escalation occurs when a low-privileged account leverages system misconfigurations to gain elevated root access.

# Audit allowed sudo privileges on local system
sudo -l

# Find files with SUID permission set
find / -perm -4000 -type f 2>/dev/null

Practice Task: Audit your local Linux development environment for binaries running with SUID permissions (`find / -perm -4000`).

Knowledge Check: Which command inspects the current user's permitted administrative sudo permissions on Linux?

Module 7: Defensive Detection & SIEM Logging

Estimated: 45 mins

# Monitor system authorization logs in real-time
tail -f /var/log/auth.log

Module 8: Ethical Penetration Testing Report Capstone

Estimated: 50 mins

Objective: Compile professional assessment findings into an executive summary, technical vulnerability matrix, and remediation roadmap.

Concept: The ultimate deliverable of ethical security testing is an actionable report that helps organizations fix vulnerabilities.

# Report Document Structure:
1. Executive Summary (For non-technical leadership)
2. Scope & Methodology
3. Detailed Technical Findings (Vulnerability, Risk Score, Evidence)
4. Remediation Prioritization Roadmap

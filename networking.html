🟢 Beginner Track

Module 1: IP Addressing & Subnetting Basics

Estimated: 30 mins

Objective: Differentiate between IPv4 vs IPv6, public vs private subnets (RFC 1918), and MAC hardware addresses.

Concept: IP addresses route data across networks logically (Layer 3), while MAC addresses deliver frames locally (Layer 2).

# Private IP Ranges (RFC 1918):
10.0.0.0 - 10.255.255.255 (10.0.0.0/8)
172.16.0.0 - 172.31.255.255 (172.16.0.0/12)
192.168.0.0 - 192.168.255.255 (192.168.0.0/16)

Practice Task: Identify whether `192.168.1.50` and `8.8.8.8` are private or public IP addresses.

Knowledge Check: Which layer of network addressing uses MAC addresses?

Module 2: OSI & TCP/IP Reference Models

Estimated: 35 mins

Objective: Map communication steps across the 7 OSI layers and compare them to the pragmatic 4-layer TCP/IP stack.

Concept: Data undergoes encapsulation as it descends layers (Data -> Segment -> Packet -> Frame -> Bits).

OSI Stack: Application > Presentation > Session > Transport > Network > Data Link > Physical

Practice Task: Trace which OSI layer is responsible for encrypting web traffic (Presentation Layer 6).

Knowledge Check: At which layer do Routers primarily operate?

Module 3: Core Ports & Service Protocols

Estimated: 30 mins

Objective: Memorize well-known port numbers (0-1023) and match them to underlying protocols.

Concept: Ports direct network traffic to specific software applications listening on a host machine.

Port 22: SSH | Port 53: DNS | Port 80: HTTP | Port 443: HTTPS

Practice Task: Inspect your local device's open ports using terminal commands learned in the Linux module (`ss -tuln`).

Knowledge Check: Which standard network port handles encrypted HTTPS traffic?

🔵 Intermediate Track

Module 4: DNS Resolution & DHCP Workflows

Estimated: 40 mins

Objective: Understand Domain Name System (DNS) query lookup cycles and dynamic IP assignment via DHCP.

Concept: DNS translates human-readable hostnames into computer-routable IP addresses (A, AAAA, MX, CNAME, TXT records).

# Query DNS records for a domain
dig example.com A +short
nslookup -type=TXT example.com

Practice Task: Perform a DNS lookup on `localhost` or a safe domain using `dig` or `nslookup`.

Knowledge Check: Which DNS record type resolves a hostname directly to an IPv4 address?

Module 5: Transport Layer: TCP vs UDP Mechanics

Estimated: 35 mins

Objective: Analyze the TCP 3-Way Handshake (SYN, SYN-ACK, ACK) vs stateless UDP streaming datagrams.

Concept: TCP prioritizes connection reliability and order; UDP prioritizes low latency speed.

TCP Handshake: Client [SYN] -> Server | Server [SYN-ACK] -> Client | Client [ACK] -> Server

Practice Task: Identify two applications that rely on UDP (DNS queries, VoIP, live video streaming).

Knowledge Check: What flag sequence initiates a connection establishment in TCP?

Module 6: HTTP/HTTPS & TLS Cryptographic Handshake

Estimated: 40 mins

Objective: Inspect HTTP request/response headers and understand asymmetric encryption during TLS negotiation.

Concept: TLS safeguards cleartext HTTP headers and body content against local eavesdropping and interception.

# Inspect HTTP response headers using curl
curl -I https://127.0.0.1

Practice Task: Fetch response headers from a local test server using `curl -I` and observe status codes.

Knowledge Check: Which HTTP response status code indicates an asset was successfully found and returned?

🟣 Advanced Track

Module 7: Routing, NAT & Firewall Fundamentals

Estimated: 45 mins

Objective: Understand Network Address Translation (NAT), default gateways, and stateful packet filtering firewalls.

Concept: NAT maps multiple private IP devices onto a single public IP to conserve address space and shield internal hosts.

# Display IP routing table on Linux
ip route show

Practice Task: Run `ip route show` or `netstat -r` to identify your network's default gateway IP.

Knowledge Check: What technology enables multiple internal devices with private IPs to share one public IP address?

Module 8: Network Troubleshooting Project

Estimated: 50 mins

Objective: Diagnose connectivity failures systematically using `ping`, `traceroute`, `dig`, and local socket analysis.

Concept: Structured troubleshooting tests layer-by-layer: Physical -> Link -> IP Routing -> DNS -> App Port.

# Troubleshooting Workflow:
1. ping 127.0.0.1 (Loopback check)
2. ping <Default_Gateway_IP> (Local LAN check)
3. ping 1.1.1.1 (Public IP routing check)
4. dig example.com (DNS resolution check)

Practice Task: Execute the 4-step diagnostic workflow locally and document any latency or packet loss.

Knowledge Check: If you can ping `1.1.1.1` but cannot browse `example.com`, where is the failure?
